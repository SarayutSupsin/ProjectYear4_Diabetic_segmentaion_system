## 🚦 รายการภารกิจตามลำดับขั้นตอนระดับละเอียด (Micro-Tasks Checklist)

### 🧱 ส่วนที่ 1: การจัดตั้งและโครงสร้างระบบฐานข้อมูล (สำเร็จแล้ว 🟢)
* [x] **งานที่ 1**: สตาร์ทเปิดใช้งานตู้ฐานข้อมูล PostgreSQL Container บนระบบ Docker Compose (`docker compose up -d db`)
* [x] **งานที่ 2**: กำหนดค่าความปลอดภัยและตัวแปรสิ่งแวดล้อมของการเชื่อมฐานข้อมูลดีบี (`.env` และ `app/core/config.py`)
* [x] **งานที่ 3**: ติดตั้งและเริ่มต้นโปรแกรมคุมเวอร์ชันโครงสร้างตารางข้อมูล Alembic Migration (`alembic init`)
* [x] **งานที่ 4**: เขียนเชื่อมสะพานจดทะเบียนตารางโมเดลหลัก 8 ตารางในแรมผ่านสคริปต์ `alembic/env.py`
* [x] **งานที่ 5**: ตั้งค่าบล็อก Logger และ Console Handler ใน `alembic.ini` เพื่อป้องกันการเกิดแครช (KeyError)
* [x] **งานที่ 6**: เขียนไฟล์พิมพ์เขียวแม่แบบ `alembic/script.py.mako` และสร้างโฟลเดอร์สำหรับเก็บประวัติย้ายตาราง `alembic/versions/`
* [x] **งานที่ 7**: วิเคราะห์เปรียบเทียบตารางและสร้างแปลนไฟล์ประวัติการขึ้นรูปตารางเปล่าตัวแรก (`alembic revision --autogenerate`)
* [x] **งานที่ 8**: สั่งรันตอกเสาเข็มเนรมิตตารางปล่าวทั้ง 8 ตารางของจริงเข้าไปใน PostgreSQL (`alembic upgrade head`)
* [x] **งานที่ 9**: เขียนสคริปต์ป้อนข้อมูลนำร่องระบบและรันเพื่อบันทึกข้อมูลสิทธิ์กับพิกดเท้า 8 โซนลงดีบีจริง (`python app/db/seed.py`)
* [x] **งานที่ 10**: ทดลองเชื่อม API ตรวจสอบการรันร่วมกับตู้ฐานข้อมูลผ่านลิงก์ `/test-db-connection` (สำเร็จแล้ว 🟢)

### 📂 ส่วนที่ 2: ระบบจัดการรูปภาพและเอนจินประมวลผลแผลเบาหวาน (AI & Calibration Engine)
* [ ] **งานที่ 11**: สร้างโฟลเดอร์รับน้ำหนักโมเดลในเซิร์ฟเวอร์หลัก `server/weights/` และคัดลอกไฟล์น้ำหนัก `best_model.pth` มาติดตั้ง
* [ ] **งานที่ 12**: ติดตั้ง Library ทางคณิตศาสตร์และการประมวลผลรูปภาพเข้าตู้คอนเทนเนอร์หลังบ้านผ่านไฟล์ `requirements.txt`
* [ ] **งานที่ 13**: เขียนโมดูลย่อย `load_model` สร้างโครงร่างคลาส U-Net (EfficientNet-B4) และดึงไฟล์น้ำหนักผ่าน CPU Mapping
* [ ] **งานที่ 14**: เขียนระบบแปลงสีรูปภาพ (BGR เป็น RGB) และปรับโครงสร้างพารามิเตอร์รูปถ่าย (PIL Image Wrapper)
* [ ] **งานที่ 15**: เขียนโมดูลการทรานส์ฟอร์ม Normalization โดยคำนวณจากค่าเฉลี่ยสากล (ImageNet Mean & Std)
* [ ] **งานที่ 16**: เขียนเอนจินรันประมวลผลแผลในแรมภายใต้คำสั่งปิดการคำนวณเกรเดียนท์ (`torch.no_grad()`) เพื่อประหยัดทรัพยากรตู้
* [ ] **งานที่ 17**: เขียนตัวคำนวณขอบเขต Probability Map ขยายขนาดกลับไปที่ขนาดดั้งเดิม (`cv2.INTER_LINEAR`) เพื่อขอบแผลเนียนคมชัด
* [ ] **งานที่ 18**: เขียนสูตรคำนวณดัชนีความไม่แน่นอนเฉลี่ยของขอบแผล (Shannon Entropy) และค่าความมั่นใจ (Confidence Score)
* [ ] **งานที่ 19**: เขียนโมดูลสแกนดีเทกหาวัตถุอ้างอิง QR Code ขนาด $2.0 \times 2.0 \text{ cm}$ ในรูปถ่ายดิบผ่านคำสั่ง `pyzbar`
* [ ] **งานที่ 20**: เขียนคำสั่ง Shoelace Formula (`cv2.contourArea`) หาพื้นที่พิกเซลจริงของ QR Code เพื่อความทนทานต่อการหมุนภาพ
* [ ] **งานที่ 21**: เขียนฟังก์ชันจัดเรียงจุดมุมกล่องสติกเกอร์ทั้ง 4 จุด (Top-Left, Top-Right, Bottom-Right, Bottom-Left)
* [ ] **งานที่ 22**: เขียนสมการหาเมตริกซ์แปลงพิกัด Homography (`cv2.getPerspectiveTransform`) วิ่งเข้าหาพิกัดกล่องกว้าง 200x200 px
* [ ] **งานที่ 23**: เขียนคำสั่งดึงระนาบภาพแผลให้ตรงและขนานกับแนวสายตาของกล้องถ่าย (`cv2.warpPerspective`)
* [ ] **งานที่ 24**: คำนวณขนาดแผลเบาหวานจริงในโลกจริงจากพิกเซลหน้าตรงด้วยตัวแปรคูณมาตราส่วนคงที่ $0.0001\text{ cm}^2$ ต่อ 1 พิกเซล
* [ ] **งานที่ 25**: เขียนระบบตีกรอบวาดเส้นขอบสีเขียวรอบแผลเบาหวาน (Contours) ลงบนรูปถ่ายเพื่อใช้อ้างอิงผลลัพธ์ทางการแพทย์
* [ ] **งานที่ 26**: พัฒนาฟังก์ชันรวบรวมค่าวิเคราะห์ (ขนาดพื้นที่แผล, ความมั่นใจ AI) คืนค่าเป็น Python Dictionary เพื่อป้อนให้ API บันทึกเข้าดีบีโดยตรง (ไม่มีการบันทึกไฟล์ JSON ดีบักลงดิสก์)
* [ ] **งานที่ 27**: เขียนสคริปต์สแกนตรวจสอบความแม่นยำเดี่ยว (`server/scratch/test_segmentation.py`) และทดสอบรัน Sandbox

### 💻 ส่วนที่ 3: ระบบบริการเชื่อมต่อข้ามเครือข่ายหลังบ้าน (FastAPI API Layer)
* [ ] **งานที่ 28**: ลงทะเบียนเปิดบริการแชร์รูปภาพและเข้าถึงรูปภาพแผลผ่านหน้าบ้าน (`app.mount("/static", StaticFiles(...))`) ใน `main.py`
* [ ] **งานที่ 29**: เขียนฟังก์ชันสร้างโฟลเดอร์สำหรับจัดเก็บรูปภาพผลลัพธ์แผล (`static/wounds/`) อัตโนมัติเมื่อเซิร์ฟเวอร์เริ่มทำงานครั้งแรก (เก็บเพียงภาพถ่ายแผลที่ล้อมเส้นขอบสีเขียวชิ้นเดียว)
* [ ] **งานที่ 30**: เขียน Pydantic Schemas ตัวแทนข้อมูลสำหรับจัดการคนไข้ (`PatientCreate`, `PatientResponse`)
* [ ] **งานที่ 31**: พัฒนาเราเตอร์ API ส่งข้อมูลลงทะเบียนเวชระเบียนคนไข้ใหม่ (`POST /api/v1/patients/`)
* [ ] **งานที่ 32**: พัฒนาเราเตอร์ API ค้นหาดึงประวัติคนไข้และรายชื่อบาดแผลคนไข้ด้วยรหัส HN (`GET /api/v1/patients/{HN}`)
* [ ] **งานที่ 33**: พัฒนาเราเตอร์ API แสดงรายชื่อเวชระเบียนคนไข้ทั้งหมดในระบบโรงพยาบาล (`GET /api/v1/patients/`)
* [ ] **งานที่ 34**: เขียน Pydantic Schemas ตัวแทนข้อมูลสำหรับจัดการจุดแผลคนไข้ (`WoundCreate`, `WoundResponse`)
* [ ] **งานที่ 35**: พัฒนาเราเตอร์ API ขึ้นทะเบียนจุดบาดแผลใหม่แยกตำแหน่งเท้า 8 บริเวณ (`POST /api/v1/wounds/`)
* [ ] **งานที่ 36**: พัฒนาเราเตอร์ API แสดงรายการจุดแผลทั้งหมดของคนไข้รายคนตามรหัส HN (`GET /api/v1/wounds/patient/{HN}`)
* [ ] **งานที่ 37**: พัฒนาเราเตอร์ API รับไฟล์รูปภาพแผลจริง ➡️ เซฟลงตู้ ➡️ ส่งไปรันเอนจิน AI ➡️ บันทึกลง Postgres (`POST /api/v1/wounds/records`)
* [ ] **งานที่ 38**: พัฒนาเราเตอร์ API ดึงประวัติภาพถ่ายและสถิติขนาดแผลย้อนหลังรายแผล (`GET /api/v1/wounds/records/{wound_id}`)
* [ ] **งานที่ 39**: เขียน Pydantic Schemas ตัวแทนข้อมูลสำหรับจัดการการนัดหมายทำแผล (`AppointmentCreate`, `AppointmentResponse`)
* [ ] **งานที่ 40**: พัฒนาเราเตอร์ API บันทึกประวัตินัดหมายการเข้าทำแผลในคลินิกเบาหวานรอบถัดไป (`POST /api/v1/appointments/`)
* [ ] **งานที่ 41**: พัฒนาเราเตอร์ API ดึงรายการการนัดหมายติดตามผลแยกตามสิทธิ์พยาบาลหรือคนไข้ (`GET /api/v1/appointments/`)
* [ ] **งานที่ 42**: ติดตั้งระบบจำกัดสิทธิ์ความปลอดภัยด้วยรหัสผ่านแฮช Bcrypt และระบบยืนยันสิทธิ์ JWT Access Token

### 🎨 ส่วนที่ 4: ส่วนแสดงผลเว็บแอปพลิเคชันหน้าบ้าน (React Frontend UI)
* [ ] **งานที่ 43**: สั่งรันขึ้นโครงสร้างระบบหน้าบ้าน React และ Vite ในห้อง `client/` พร้อมตั้งชื่อสเปคไฟล์ตั้งค่า
* [ ] **งานที่ 44**: ติดตั้ง Dependencies สำคัญของหน้าบ้าน (Axios สำหรับดึง API, React Router, Chart.js สำหรับวาดกราฟเส้นสถิติแผล)
* [ ] **งานที่ 45**: จัดโครงสร้างเราเตอร์หน้าเว็บ React แยกหน้าตามสิทธิ์ของผู้ดูแลระบบ พยาบาล และคนไข้เบาหวาน
* [ ] **งานที่ 46**: พัฒนา UI หน้าจอล็อกอินสมาชิก (Login Screen) แยกตามสิทธิ์การเข้าถึงข้อมูลระบบการรักษา
* [ ] **งานที่ 47**: พัฒนา Dashboard ผู้ดูแลระบบ (Admin UI) เพื่อใช้คุมสิทธิ์ สร้าง แก้ไข และระงับสิทธิ์การใช้งานบัญชีต่าง ๆ ในโรงพยาบาล
* [ ] **งานที่ 48**: พัฒนา Dashboard พยาบาล (Nurse UI) แสดงรายการคนไข้ ค้นหาด้วยรหัส HN และแบบฟอร์มลงประวัติผู้ป่วยใหม่
* [ ] **งานที่ 49**: พัฒนาหน้าจอส่งสแกนวิเคราะห์ภาพถ่ายแผล (Nurse Scan UI) มีระบบดึงภาพ AI และเปรียบเทียบภาพดิบ/ภาพหน้าตรงข้างแผล
* [ ] **งานที่ 50**: พัฒนา Dashboard คนไข้ (Patient UI) เพื่อสืบค้นข้อมูลประวัติและรูปบาดแผลของตนเองรายครั้ง
* [ ] **งานที่ 51**: พัฒนาหน้าจอพล็อตกราฟเส้นติดตามประวัติแผลเบาหวานคนไข้ เพื่อแสดงผลแนวโน้มอัตราการสมานแผลหดตัวลงย้อนหลัง
* [ ] **งานที่ 52**: เชื่อมต่อประกอบระบบ API เข้ากันแบบสมบูรณ์ และทดสอบกระบวนการรันจริงข้ามเน็ตเวิร์ก Docker (CORS Setup)
