# 🩺 คู่มือการตรวจทานคณิตศาสตร์ของระบบวัดขนาดแผล (Mathematical Verification Guide)

> [!NOTE]
> **📋 สรุปอัลกอริทึมและตรรกะคำนวณ (System Algorithms & Logics Summary):**
> ระบบประยุกต์ใช้คอมพิวเตอร์วิทัศน์และปัญญาประดิษฐ์ในการตรวจวัดพื้นที่แผลเบาหวานผ่านหลักการทำงาน ดังนี้:
> 
> 1. **การหาพิกัดและตำแหน่งสติกเกอร์ QR Code (QR Code Detection & Localization)**
>    * *หลักการ:* ตรวจจับจุดอ้างอิงและ Finder Patterns สี่เหลี่ยมมุมสติกเกอร์ QR Code อ้างอิงเพื่อถอดพิกัดจุดยอด (เรียงตามเข็มนาฬิกา)
>    * *ตัวอย่างการคำนวณ:* สแกนจุดมุมทั้ง 4 ของสติกเกอร์ QR Codeบนระนาบภาพดิบ ได้พิกัดยอด: ซ้ายบน = [432, 660], ซ้ายล่าง = [467, 580], ขวาล่าง = [548, 615], ขวาบน = [513, 697]
>    * *ผลลัพธ์:* พิกัด 4 จุดมุมสำหรับเป็นจุดตั้งต้นในการคำนวณปรับแก้ความลาดเอียงของกล้อง
> 
> 2. **การวัดขอบความกว้างความสูงของรูปดิบ (Euclidean Distance)**
>    * *หลักการ:* หาสเกลกล้องจริงโดยวัดระยะห่างระหว่างมุมภาพด้วยสมการ: d = sqrt( (x2 - x1)^2 + (y2 - y1)^2 )
>    * *ตัวอย่างการคำนวณ:* ความยาวขอบสติกเกอร์ QR Codeบนภาพดิบจากจุด [432, 660] ไป [467, 580] = sqrt( (467 - 432)^2 + (580 - 660)^2 ) = 87.32 พิกเซล
>    * *ผลลัพธ์:* ความกว้าง/ความสูงพิกเซลเฉลี่ยของสติกเกอร์ QR Code ดิบ (88.44 px) เพื่อหามาตราส่วนความหนาแน่นพิกเซลกล้องดิบ (44.22 px/cm)
> 
> 3. **การประเมินพื้นที่รวมภาพดิบ (Shoelace Formula)**
>    * *หลักการ:* คำนวณพื้นที่รูปสี่เหลี่ยมบิดเบี้ยวจากมุมยอดด้วยสูตรคูณไขว้ทแยง: Area = 0.5 * |(x1*y2 + x2*y3 + x3*y4 + x4*y1) - (y1*x2 + y2*x3 + y3*x4 + y4*x1)|
>    * *ตัวอย่างการคำนวณ:* ผลบวกคูณลง = 1,258,301 | ผลรวมคูณขึ้น = 1,242,659 | พื้นที่สติกเกอร์ QR Code เอียง = |1,258,301 - 1,242,659| / 2 = 7,821.0 พิกเซล
>    * *ผลลัพธ์:* พื้นที่พิกเซลรวมของสติกเกอร์ QR Codeบนรูปดิบ เพื่อใช้วันอัตราเบี่ยงเบนสัมพัทธ์ในรายงานดีบั๊ก
> 
> 4. **การทำเซกเมนเทชันแยกแผล (Wound Segmentation using U-Net)**
>    * *หลักการ:* แบ่งแยกพิกเซลแผลออกจากผิวปกติ (Semantic Segmentation) ด้วยปัญญาประดิษฐ์ U-Net ร่วมกับ EfficientNet-B4 Backbone
>    * *ตัวอย่างการคำนวณ:* ย่อภาพอินพุตเหลือ 512 x 512 พิกเซล ทำนายหาความน่าจะเป็นในการเป็นแผล (0.0 ถึง 1.0) หากความมั่นใจเกิน 0.5 (Threshold = 0.5) จะปัดเป็นแผล (สีขาว = 255)
>    * *ผลลัพธ์:* หน้ากากภาพแผลขาวดำ (Binary Mask) ที่ระบุตำแหน่งบาดแผลได้คมชัด
> 
> 5. **การประมาณขยายสเกลความละเอียดแผล (Bilinear Interpolation)**
>    * *หลักการ:* ขยายขนาดหน้ากากภาพผลลัพธ์โดยสุ่มเฉลี่ยน้ำหนักพิกเซลข้างเคียงรอบตัว 4 จุด เพื่อให้ขอบไม่หยักเป็นฟันปลา
>    * *ตัวอย่างการคำนวณ:* ขยายสัดส่วนของ Binary Mask แผลจากมิติ 512 x 512 พิกเซล กลับคืนสู่ความละเอียดภาพถ่ายดั้งเดิมคือ 896 x 1195 พิกเซล
>    * *ผลลัพธ์:* หน้ากากแผลที่มีขอบเรียบเนียนคมชัด อยู่ในมิติระดับความละเอียดตั้งต้นภาพถ่ายจริง
> 
> 6. **การบิดภาพตรงชดเชยการเอียงกล้อง (Planar Homography Warp)**
>    * *หลักการ:* คำนวณเมทริกซ์ 3x3 ด้วยทฤษฎีเรขาคณิตโปรเจกทีฟ เพื่อดัดปรับ Perspective ภาพและ Mask แผลให้เป็นมุมหน้าตรง 90 องศาขนานหน้ากล้อง
>    * *ตัวอย่างการคำนวณ:* แมปพิกัดสติกเกอร์ QR Code เอียง [432, 660]... ไปยังพิกัดสเกลไม้บรรทัดดิจิทัลเป้าหมาย [0, 0]... เพื่อคำนวณหักล้างการหดลีบพื้นที่ตามมุมเอียง (Perspective Cosine Law of Area Projection)
>    * *ผลลัพธ์:* ภาพหน้าตรง (Warped Image) ที่มีสเกลคงที่มาตรฐานกลาง และได้ขนาดสัดส่วนแผลจริงไม่บิดเบี้ยว
> 
> 7. **การวัดขนาดพื้นที่แผลตารางเซนติเมตรจริง (Wound Area Scaling)**
    * *หลักการ:* คำนวณหาพื้นที่แผลโดยอิงสูตรหลักสองขั้นตอนจากเล่มโครงร่างวิจัย:
      1. Scale Factor = 4 / พื้นที่ QR Code (หน่วยเป็น cm²/pixel)
      2. พื้นที่แผลจริง (cm²) = จำนวนพิกเซลแผล * Scale Factor
    * *ตัวอย่างการคำนวณ:*
      • ระบบใหม่ (แก้เอียง): Scale Factor = 4 / 40,000 = 0.0001 | พื้นที่แผล = 25,198 * 0.0001 = **2.5198 ตารางเซนติเมตร**
      • ระบบเก่า (ไม่แก้เอียง): Scale Factor = 4 / 7,821.0 = 0.00051144 | พื้นที่แผล = 4,552 * 0.00051144 = **2.3280 ตารางเซนติเมตร**
    * *ผลลัพธ์:* ได้มาตราส่วนและการคำนวณพื้นที่แผลที่ตรงตามเล่มโครงร่างวิจัยอย่างถูกต้อง

## 📌 บทที่ 1: การแบ่งกลุ่มการคำนวณในระบบ (Classification of Calculations)

เพื่อความถูกต้อง ชัดเจน และโปร่งใสในการตรวจสอบระบบวัดขนาดบาดแผล โครงสร้างข้อมูลทางคณิตศาสตร์ในระบบได้ถูกแบ่งแยกออกเป็น 2 กลุ่มอย่างชัดเจน ดังนี้:

### 1.1 ส่วนที่ใช้งานจริงในระบบ (Production Calculations)
คือกลุ่มของข้อมูลและคณิตศาสตร์ที่ **ตัวโปรแกรมหลักนำไปรันประมวลผลและคำนวณจริง ๆ** เพื่อให้ได้ขนาดพื้นที่แผลปลายทางออกมาในหน่วยตารางเซนติเมตร ข้อมูลกลุ่มนี้จะใช้โครงสร้างคงที่ในการจัดระเบียบระนาบภาพตรงขนาด 200 x 200 พิกเซล และค่าตัวคูณพื้นที่คงที่ 0.0001 เสมอ ประกอบด้วย:
* พิกัดจุดมุมสติกเกอร์ QR Codeที่บิดเอียงจริงบนภาพดิบ (Source Points)
* พิกัดจุดเป้าหมายหน้าตรงที่คงที่และได้มาตรฐาน (Destination Points)
* จำนวนพิกเซลของบาดแผลหลังจากผ่านการจัดระเบียบภาพตรงแล้ว (Rectified Pixel Area)

### 1.2 ส่วนที่ใช้ดีบั๊กและตรวจสอบคณิตศาสตร์ (Audit & Debug Calculations)
คือกลุ่มของสมการและตัวเลขที่ **คำนวณเสริมขึ้นมาเพื่อประเมินความเพี้ยนเชิงทัศนมิติเชิงคณิตศาสตร์** ข้อมูลเหล่านี้จะแสดงผลออกมาในฟิลด์ `calibration_debug` ของไฟล์ JSON และใช้เขียนบรรยายเปรียบเทียบเชิงวิจัยเท่านั้น **ตัวระบบจริงไม่ได้นำค่าเหล่านี้ไปคูณหาขนาดแผลปลายทาง** ประกอบด้วย:
* ระยะทางแบบ Euclidean ของขอบ QR Code ดิบทีละด้าน
* ความหนาแน่นพิกเซลของกล้องดิบเฉลี่ย (Camera Scale Density)
* พื้นที่พิกเซลของสติกเกอร์ QR Codeบนภาพดิบด้วยสูตรคูณไขว้ทแยง (Shoelace Formula)
* ค่าตัวคูณพื้นที่ดิบสมมติกรณีไม่ปรับแก้ความเอียง (Original Scale Factor)

---

### 1.3 ทฤษฎีการบิดเบือนพื้นที่ตามมุมเอียง (Perspective Distortion & Cosine Law)

ในทางฟิสิกส์ทัศนศาสตร์ เมื่อกล้องสมาร์ทโฟนทำมุมเอียง (Camera Tilt Angle) กับพื้นผิวของบาดแผล แทนที่จะถ่ายแบบหน้าตรงคู่ขนาน:
1. **มิติด้านความยาวของแผลในทิศทางที่กล้องเอียง** จะถูกมองเห็นสั้นลงตามกฎของโคไซน์ (Cosine Law):
   ความยาวที่ปรากฏ = ความยาวจริง * cos(มุมเอียงกล้อง)
2. **ขนาดพื้นที่แผลที่ปรากฏบนรูปภาพดิบ** จึงหดตัวลดลงตามสัดส่วนมุมเอียง:
   พื้นที่ปรากฏบนรูปดิบ = พื้นที่จริง * cos(มุมเอียงกล้อง)

#### ตัวอย่างแสดงผลกระทบของการเอียงกล้องจริง:
* **กรณีถ่ายเอียงทำมุม 30 องศา** (เกิดขึ้นบ่อยเมื่อผู้ป่วยถ่ายรูปแผลด้วยตัวเอง):
  * ค่า cos(30 องศา) = 0.866
  * พื้นที่แผลที่วัดได้บนรูปภาพดิบจะหดเล็กลง เหลือเพียง 86.6% ของพื้นที่จริง (หายไปถึง 13.4%)
* **กรณีถ่ายเอียงทำมุม 45 องศา**:
  * ค่า cos(45 องศา) = 0.707
  * พื้นที่แผลที่วัดได้จะลดลงเหลือเพียง 70.7% (หายไปมากถึง 29.3%) ซึ่งเป็นความคลาดเคลื่อนที่ส่งผลเสียต่อการวินิจฉัยทางการแพทย์อย่างยิ่ง

#### วิธีแก้ไขด้วยระบบ Homography:
การแปลง Homography (Warping) จะคำนวณหามุมบิดเบี้ยวของกล้องจากการวิเคราะห์สติกเกอร์ QR Code แล้วสร้างระนาบจำลองเสมือนจริงขึ้นมาใหม่ เพื่อดัดดึงหน้าตาภาพกลับคืนมาสู่มุมมองตั้งฉาก (Orthogonal view) ซึ่งเป็นการหักล้างตัวคูณ cos(มุมเอียงกล้อง) ออกไป ทำให้ระบบสามารถกู้คืนพื้นที่จริงของแผลเบาหวานกลับมาได้ถูกต้อง 100% ไม่ว่าจะถ่ายเอียงกี่องศาก็ตาม

## 📌 บทที่ 2: ส่วนที่ใช้งานจริงในระบบ (Production System Pipeline)

การดำเนินงานของระบบเพื่อหาขนาดพื้นที่บาดแผลของผู้ป่วยโรคเบาหวาน (Diabetic Foot Ulcer) มีลำดับขั้นตอนการคำนวณอย่างละเอียดทีละขั้น ดังนี้:

### ขั้นตอนที่ 2.1: การเตรียมรูปภาพ (Image Preprocessing)
* **การทำงาน:** เมื่อระบบได้รับรูปภาพแผลต้นฉบับ (ความละเอียดดั้งเดิม กว้าง 896 x สูง 1195 พิกเซล) เข้ามา โค้ดจะทำการปรับย่อขนาดภาพด้วยวิธีมาตรฐานให้กลายเป็นขนาด **512 x 512 พิกเซล** เพื่อใช้ป้อนเข้าสู่โมเดล AI ในขั้นตอนถัดไป

### ขั้นตอนที่ 2.2: การทำนายหาพื้นที่แผลดิบ (AI Segmentation with U-Net)
* **การทำงาน:** ภาพขนาด 512 x 512 พิกเซลจะถูกประมวลผลผ่านโมเดลปัญญาประดิษฐ์ U-Net เพื่อตรวจหาขอบเขตเนื้อแผล โดยผลลัพธ์ของพิกเซลจะถูกบีบด้วยฟังก์ชัน Sigmoid Activation ให้มีค่าระดับความน่าจะเป็นในการเป็นเนื้อแผลอยู่ระหว่าง 0.0 ถึง 1.0 เสมอ

### ขั้นตอนที่ 2.3: การขยายสัดส่วนแผนผังความน่าจะเป็นกลับสู่ขนาดเดิม (Bilinear Interpolation)
* **การทำงาน:** เพื่อให้หน้ากากของพื้นที่แผลมีความละเอียดเนียนคมชัดสอดคล้องตามพิกเซลของกล้องถ่ายรูปดั้งเดิม โค้ดจะนำแผนผังความน่าจะเป็นขนาด 512 x 512 พิกเซล มาขยายมิติกว้างยาวกลับคืนไปที่ขนาดภาพถ่ายดั้งเดิมคือ **896 x 1195 พิกเซล** โดยใช้ตรรกะ Bilinear Interpolation

### ขั้นตอนที่ 2.4: การคัดแยกขอบเขตเนื้อแผลขาวดำ (Binary Thresholding)
* **การคำนวณ:** นำพิกเซลในแผนผังความน่าจะเป็นขนาด 896 x 1195 พิกเซลที่ผ่านการขยายขนาดแล้ว มาผ่านเกณฑ์ชี้ขาดค่าคงที่ในระบบคือ 0.5 (Threshold = 0.5):
  * พิกเซลใด ๆ ที่มีระดับความน่าจะเป็นมากกว่า 0.5 จะถูกปัดเป็นพื้นที่แผล (สีขาว = 255)
  * พิกเซลใด ๆ ที่มีระดับความน่าจะเป็นน้อยกว่าหรือเท่ากับ 0.5 จะถูกปัดเป็นผิวหนังปกติ (สีดำ = 0)
* **ผลลัพธ์ที่นับได้:** ระบบสแกนนับพิกเซลสีขาวที่เป็นแผลจากรูปภาพดิบสะสมได้เท่ากับ **4,552 พิกเซล** (ตรงกับค่า `raw_wound_pixel_area` ในระบบดีบั๊ก)

### ขั้นตอนที่ 2.5: การคำนวณหาเมทริกซ์การปรับระนาบตรง (Homography Matrix Calculation)
* **หลักการทำงาน:** กล้องสมาร์ทโฟนที่คนไข้ใช้ถ่ายรูปจะเอียงเฉียงก้มเงยบิดเบี้ยวตามมุมมือถือ ระบบจึงต้องใช้คณิตศาสตร์ความสัมพันธ์แบบโปรเจกทีฟยืดระนาบให้เป็นหน้าตรง
* **จุดอ้างอิงนำสเกล:** ระบบทำการตรวจจับสติกเกอร์ QR Code ด้วยไลบรารี Pyzbar โดยจุดพิกัด 4 จุดมุมของ QR Code ที่ดึงออกมาได้ จะถูกจัดลำดับพิกัดเริ่มต้นตามแนวแกนหัวตั้งของตัวสติกเกอร์ QR Codeเสมอ:
  * **พิกัดภาพดิบที่ตรวจพบจริง (Source Points):**
    * ซ้ายบน (Top-Left): [432, 660] (qr_polygon[0])
    * ซ้ายล่าง (Bottom-Left): [513, 697] (qr_polygon[1]) (แกนจอตกลงมาต่ำกว่า)
    * ขวาล่าง (Bottom-Right): [548, 615] (qr_polygon[2])
    * ขวาบน (Top-Right): [467, 580] (qr_polygon[3]) (แกนจอย่อขึ้นไปสูงกว่า)
  * **พิกัดระนาบตรงเป้าหมายที่ล็อกขนาดไว้ (Destination Points):**
    * ซ้ายบน (Top-Left): [0.0, 0.0]
    * ขวาบน (Top-Right): [200.0, 0.0]
    * ขวาล่าง (Bottom-Right): [200.0, 200.0]
    * ซ้ายล่าง (Bottom-Left): [0.0, 200.0]
* **การคำนวณคณิตศาสตร์ในโค้ด:**
  นำจุดจับคู่ทั้ง 4 คู่พิกัดส่งเข้าฟังก์ชัน cv2.getPerspectiveTransform(src_pts, dst_pts) เพื่อคำนวณแก้สมการเมทริกซ์การแปลงขนาด 3x3 ซึ่งระบุความสัมพันธ์ในการเปลี่ยนทิศทางเชิงมิติ

### ขั้นตอนที่ 2.6: การยืดระนาบภาพเพื่อแก้ความลาดเอียงและป้องกันขอบแหว่ง (Perspective Warping with Translation)
* **ปัญหาขอบภาพขาดหาย:** หากทำการดึงระนาบตรงเข้าหาพิกัด [0, 0] ของสติกเกอร์ QR Codeตรง ๆ พิกเซลส่วนอื่นของรูปภาพหรือแผลที่อยู่เยื้องไปทางซ้ายหรือด้านบนของสติกเกอร์ QR Codeจะมีค่าพิกัดการคำนวณเป็น "ติดลบ" ส่งผลให้พิกเซลเหล่านั้นตกขอบภาพและแหว่งหายไป
* **คณิตศาสตร์การแก้ไขด้วยการเลื่อนแกนพิกัด (Translation Matrix):**
  1. โค้ดคำนวณหาตำแหน่งติดลบที่ลึกที่สุด (ค่า min_x และ min_y) ล่วงหน้าจากสี่มุมของภาพถ่าย
  2. สร้างเมทริกซ์การเลื่อนตำแหน่ง (Translation Matrix: T) ขนาด 3x3 เพื่อขยับแกนให้เป็นบวกทั้งหมด:
     T = [[1, 0, -min_x], [0, 1, -min_y], [0, 0, 1]]
  3. นำเมทริกซ์การเลื่อนมาคูณรวมประกอบกับ Homography Matrix ดั้งเดิม (H) ได้เป็นเมทริกซ์แปลงสุดท้าย:
     H_final = T x H
  4. ทำการขยายขอบเขตพิกัดเฟรมภาพรวมปลายทางทั้งหมดให้มีขนาดใหญ่ขึ้นเป็น กว้าง **3355 x สูง 3130 พิกเซล** เพื่อไม่ให้เนื้อแผลหลังยืดตรงโดนขอบรูปตัดขาดหายไป
  5. ดึงระนาบของทั้งภาพดิบและหน้ากาก (Mask) แผล:
     warped_mask = cv2.warpPerspective(mask, H_final, (3355, 3130))

> [!NOTE]
> **ภาพจำลองเปรียบเทียบ (Intuitive Analogy):**
> * **รูปถ่ายดิบ:** เปรียบเหมือนเรามีรูปแผลและรูปสติกเกอร์ QR Code วาดอยู่บนกระดาษแผ่นหนึ่ง
> * **การดึงระนาบตรงเข้า [0, 0] แบบไม่มีการแก้ไข:** จะเหมือนเราพยายามเอาตัวสติกเกอร์ QR Codeไปปักหมุดไว้ที่ "หัวมุมโต๊ะซ้ายบนสุดพอดีเป๊ะ" ทำให้กระดาษซีกซ้ายและด้านบนล้นตกโต๊ะขาดหายไปในความมืด
> * **การนำเมทริกซ์เลื่อนแกน (Translation Matrix) มาใช้งาน:** จะเหมือนเราสั่งขยับเลื่อนกระดาษทั้งแผ่นถอยเข้ามาวางให้อยู่บนโต๊ะทั้งหมด ส่งผลให้สติกเกอร์ QR Codeย้ายตำแหน่งมาอยู่ในกรอบหน้าโต๊ะ (เช่น พิกัด X = 1200, Y = 800) แต่รูปแผลและผิวหนังส่วนที่เคยล้นขอบตกโต๊ะจะขยับขึ้นมาแสดงผลครบถ้วน 100% โดยขนาดพิกเซลของสติกเกอร์ QR Codeยังคงกว้างยาวคงที่ 200 x 200 พิกเซลเท่าเดิมเสมอ

### ขั้นตอนที่ 2.7: การคำนวณหาพื้นที่แผลตารางเซนติเมตรจริง (Wound Area Calculation)
* **การคำนวณ:**
  1. ระบบทำการสแกนนับจำนวนพิกเซลแผลสีขาวบนภาพยืดระนาบตรงได้สะสมเท่ากับ **25,198 พิกเซล** (ตรวจสแกนจากหน้ากาก Binary Mask)
  2. การคำนวณพื้นที่แผลจริงหน่วยตารางเซนติเมตร อ้างอิงตามสมการหลักสองขั้นตอนจากเล่มโครงร่างวิจัย:
     * **สูตรที่ 1: การหา Scale Factor**
       Scale Factor = 4 / พื้นที่ QR Code
     * **สูตรที่ 2: การคำนวณพื้นที่แผลจริง**
       พื้นที่แผลจริง (cm²) = จำนวนพิกเซลแผล x Scale Factor
     
     * *การคำนวณเปรียบเทียบระหว่างระบบเก่า (ไม่แก้เอียง) กับระบบใหม่ (แก้เอียง):*
       * **ระบบเก่า (ไม่แก้เอียง - รูปดิบ):**
         - พื้นที่ QR Code = 7,821.0 พิกเซล (คำนวณด้วยสูตร Shoelace)
         - Scale Factor = 4 / 7,821.0 = **0.00051144**
         - จำนวนพิกเซลแผล = 4,552 พิกเซล (พิกเซลแผลดิบก่อน Warp)
         - พื้นที่แผลจริง = 4,552 x 0.00051144 = **2.3280 ตารางเซนติเมตร**
       * **ระบบใหม่ (แก้เอียงด้วย Homography):**
         - พื้นที่ QR Code = 40,000 พิกเซล (หลัง Warp ปรับตรงขนาด 200 x 200 พิกเซล)
         - Scale Factor = 4 / 40,000 = **0.0001**
         - จำนวนพิกเซลแผล = 25,198 พิกเซล (พิกเซลแผลตรงหลัง Warp)
         - พื้นที่แผลจริง = 25,198 x 0.0001 = **2.5198 ตารางเซนติเมตร**

> [!IMPORTANT]
> **📌 เหตุผลเชิงเรขาคณิตภาพถ่าย (Mathematical Necessity of a Fixed Anchor):**
> ตัวสมการคณิตศาสตร์ Homography สามารถคำนวณแก้ความเอียงเฉียงของรูปภาพให้กลับมาหน้าตรงได้ แต่**ระบบคำนวณจะไม่สามารถล่วงรู้หรือกำหนดมาตราส่วนหน่วยวัดเซนติเมตรจริงได้ด้วยตัวเอง** หากไม่มีการตั้งพิกัดอ้างอิงจุดหมายปลายทาง 
> ดังนั้น ระบบจึงต้องมีการฟิกพิกัดเป้าหมาย QR Code ปลายทางไว้คงที่ (เช่น 200x200 พิกเซล สำหรับขนาดวัตถุอ้างอิงจริง 2.0x2.0 เซนติเมตร) เพื่อเป็น **"หลักหมุดอ้างอิงเชิงมาตราส่วน (Scale Reference Anchor)"** ทำให้เราได้อัตราสเกลควบคุมหน้าตรงคงตัวที่ 1 เซนติเมตร เท่ากับ 100 พิกเซลเสมอ การยืดหดดัดหน้าตรงจึงมีความถูกต้องแม่นยำทางสัดส่วนจริง

> [!TIP]
> **⚖️ ข้อดีและข้อเสียของการกำหนดพิกัดเป้าหมาย QR Code คงที่ (200x200 พิกเซล) ในกระบวนการ Homography:**
> * **ข้อดี (Pros):**
>   1. **การคงตัวของสเกลภาพปลายทาง (Deterministic Scale Control):** การฟิกขนาดพิกัดเป้าหมายปลายทาง (dst_pts) ให้คงที่ 200x200 พิกเซล (100 พิกเซลต่อเซนติเมตร) ทำให้ภาพหน้าตรงปลายทางที่ได้มีมาตรฐานมาตราส่วนเดียวกันเสมอ สะดวกมากต่อการประเมินเทียบขนาดแผลเชิงเวลาหรือการซ้อนทับภาพ
>   2. **ขจัดผลกระทบจากระยะกล้องถ่าย (Distance Invariance):** ไม่ว่าภาพถ่ายดิบจะอยู่ใกล้หรือไกล ซึ่งปกติส่งผลให้สติกเกอร์และแผลในพิกเซลดิบมีขนาดเล็กใหญ่ต่างกัน แต่กระบวนการ Homography จะทำการยืดหรือหดสเกล QR Code ให้เป็น 200x200 พิกเซล เท่ากันเสมอ ส่งผลให้ความเพี้ยนของสเกลที่เกิดจากระยะทางกล้องหดหายไปจากภาพคำนวณ
>   3. **ความคงตัวของค่ามาตราส่วนพื้นที่:** ทำให้ค่า Scale Factor คงที่กลางอยู่ที่ 0.0001 ตารางเซนติเมตรต่อพิกเซล เสมอ ทำให้เขียนฐานข้อมูลหลังบ้านเก็บค่าคงที่ได้เสถียร
> * **ข้อเสีย (Cons):**
>   1. **สูญเสียความละเอียดภาพความคมชัดสูง (Downsampling Loss):** หากผู้ใช้ถ่ายภาพจ่อแผลในระยะใกล้มาก (ตัว QR Code ดิบมีความละเอียด 600x600 พิกเซล) การคำนวณบีบย่อให้เหลือ 200x200 พิกเซล จะทำให้โปรแกรมต้องทำ Downsample ทิ้งรายละเอียดความคมชัดสูงบางส่วนของขอบแผลและผิวหนังไป
>   2. **ภาพแตกเบลอเมื่อถ่ายรูปไกลเกินไป (Upsampling Blur):** หากรูปแผลถูกถ่ายจากระยะไกลลิบ จน QR Code ดิบมีขนาดเล็กจิ๋ว (เช่น 60x60 พิกเซล) การที่ Homography บังคับขยายพิกัดเป็น 200x200 พิกเซล จะเกิดความเบลอจากการสุ่มพิกเซล (Interpolation Blur) และลดความแม่นยำในการวัดพื้นที่แผลขอบนอก


## 📌 บทที่ 3: ส่วนที่ใช้ดีบั๊กและตรวจสอบเชิงคณิตศาสตร์ (Audit & Debug Calculations)

ตัวเลขและขั้นตอนกลุ่มนี้คำนวณขึ้นมาเพื่อประเมินความเบี่ยงเบนและส่งออกรายงานดีบั๊กใน JSON เท่านั้น **ระบบไม่ได้นำค่าเหล่านี้ไปใช้คูณหาพื้นที่แผลจริงปลายทาง**

### ขั้นตอนที่ 3.1: การคำนวณความยาวขอบสติกเกอร์ QR Code ดิบทีละด้าน (Euclidean Distance)
ตรวจวัดระยะขอบพิกเซลบนภาพถ่ายดิบของกล้องเพื่อดูค่าความเบี้ยวของแกน โดยคำนวณระยะขอบอ้างอิงตามทิศตัวสติกเกอร์ QR Code:
* **สูตรคณิตศาสตร์ระยะทาง:** d = sqrt( (x2 - x1)^2 + (y2 - y1)^2 )
* **แทนค่าขอบทั้ง 4 ด้านตามลำดับจุดยอด:**
  1. **ขอบบน (ระยะจาก Local TL ไป Local TR):** ลากจาก `[432, 660]` ไป `[467, 580]`
     d_top = sqrt( (467 - 432)^2 + (580 - 660)^2 ) = sqrt( 1225 + 6400 ) = **87.32 พิกเซล**
  2. **ขอบล่าง (ระยะจาก Local BL ไป Local BR):** ลากจาก `[513, 697]` ไป `[548, 615]`
     d_bottom = sqrt( (548 - 513)^2 + (615 - 697)^2 ) = sqrt( 1225 + 6724 ) = **89.16 พิกเซล**
  3. **ขอบซ้าย (ระยะจาก Local TL ไป Local BL):** ลากจาก `[432, 660]` ไป `[513, 697]`
     d_left = sqrt( (513 - 432)^2 + (697 - 660)^2 ) = sqrt( 6561 + 1369 ) = **89.05 พิกเซล**
  4. **ขอบขวา (ระยะจาก Local TR ไป Local BR):** ลากจาก `[467, 580]` ไป `[548, 615]`
     d_right = sqrt( (548 - 467)^2 + (615 - 580)^2 ) = sqrt( 6561 + 1225 ) = **88.24 พิกเซล**

### ขั้นตอนที่ 3.2: การหาความหนาแน่นพิกเซลกล้องดิบเฉลี่ย (Camera Scale Density)
คำนวณสเกลกล้องเฉลี่ย ณ จุดถ่ายภาพจริงของคนไข้ก่อนปรับแก้มุมเอียง:
* **ความยาวเฉลี่ย 4 ด้าน:** (89.05 + 88.24 + 87.32 + 89.16) / 4 = **88.44 พิกเซล**
* **สเกลพิกเซลต่อเซนติเมตร:** camera_px_per_cm = 88.44 พิกเซล / 2.0 เซนติเมตร = **44.22 พิกเซลต่อเซนติเมตร**

### ขั้นตอนที่ 3.3: การวิเคราะห์ขนาดเซนติเมตรสติกเกอร์ QR Codeบนรูปดิบ
หาความเบี้ยวสัมพัทธ์ในแนวตั้งแนวนอนของภาพดิบ:
* **ความกว้างพิกเซลเฉลี่ย (ขอบบนและขอบล่าง):** (87.32 + 89.16) / 2 = **88.24 พิกเซล**
  * คิดเป็นขนาดเซนติเมตร: raw_qr_width_cm = 88.24 / 44.22 = **1.995 เซนติเมตร**
* **ความยาวพิกเซลเฉลี่ย (ขอบซ้ายและขอบขวา):** (89.05 + 88.24) / 2 = **88.65 พิกเซล**
  * คิดเป็นขนาดเซนติเมตร: raw_qr_height_cm = 88.65 / 44.22 = **2.005 เซนติเมตร**

### ขั้นตอนที่ 3.4: การหาพื้นที่สติกเกอร์ QR Codeบนรูปดิบ (Shoelace Formula)
คำนวณพื้นที่พิกเซล 2 มิติรวมของสติกเกอร์ QR Codeที่เอียงจริงบนภาพดิบ:
* **สูตรคูณไขว้ทแยง:** Area = 0.5 x |(x1.y2 + x2.y3 + x3.y4 + x4.y1) - (y1.x2 + y2.x3 + y3.x4 + y4.x1)|
* **แทนค่าพิกัดจุดจริง:**
  * ผลคูณทแยงลง: (432 x 580) + (467 x 615) + (548 x 697) + (513 x 660) = 1,258,301
  * ผลคูณทแยงขึ้น: (660 x 467) + (580 x 548) + (615 x 513) + (697 x 432) = 1,242,659
  * ผลลัพธ์พื้นที่พิกเซล: |1,258,301 - 1,242,659| / 2 = **7,821.0 พิกเซล** (ได้ค่า `raw_qr_pixel_area`)

### ขั้นตอนที่ 3.5: การคำนวณตัวคูณพื้นที่รูปดิบสมมติ (Original Scale Factor)
คำนวณหาตัวคูณพื้นที่พิกเซลเป็นตารางเซนติเมตรกรณีไม่ปรับแก้ความลาดเอียงของกล้อง:
* **การคำนวณ:** original_scale_factor = 4.0 ตารางเซนติเมตร / 7821.0 พิกเซล = **0.00051144**

## 📌 บทที่ 4: การเปรียบเทียบผลลัพธ์และบทพิสูจน์ทางคณิตศาสตร์ (Analysis & Invariance Proof)

### 4.1 ตารางเปรียบเทียบผลลัพธ์ในเล่มวิจัย (Old vs. New Formulas)
เพื่อแสดงให้เห็นประสิทธิภาพของการชดเชยมุมกล้องเอียงอย่างชัดเจน:

| รูปแบบการคำนวณ | สูตรคณิตศาสตร์ที่ใช้ | การแทนค่าคำนวณ | ผลลัพธ์ที่ได้ |
| :--- | :--- | :--- | :--- |
| **ระบบเก่า (ไม่แก้เอียง)** | พิกเซลแผลดิบ x ตัวคูณพื้นที่ดิบสมมติ | 4552 x 0.00051144 | **2.3280 ตร.ซม.** |
| **ระบบใหม่ (แก้เอียง Homography)** | พิกเซลแผลตรง x ตัวคูณพื้นที่ตรงคงที่ | 25198 x 0.0001 | **2.5198 ตร.ซม.** |

* **การคำนวณเปอร์เซ็นต์ความคลาดเคลื่อนที่ได้รับการแก้ไข (Error Correction Proof):**
  สูตรคำนวณ: เปอร์เซ็นต์ความคลาดเคลื่อน = ((พื้นที่แผลหน้าตรง - พื้นที่แผลรูปดิบ) / พื้นที่แผลรูปดิบ) * 100
  แทนค่าคำนวณ: ((2.5198 - 2.328) / 2.328) * 100 = **8.24 เปอร์เซ็นต์**
  *สรุป:* หากคนไข้ถ่ายภาพเอียงก้มเงยแล้วระบบไม่ได้ใช้ Homography ปรับระนาบตรง ขนาดแผลที่วัดได้จะ **ต่ำกว่าความเป็นจริงถึง 8.24%** ซึ่งระบบแบบใหม่สามารถกู้คืนพื้นที่แผลที่ขาดหายไปกลับมาได้สมบูรณ์

### 4.2 บทพิสูจน์การหักล้างของขนาดระนาบตรง (Resolution Invariance Proof)
เพื่อตอบคำถามกรรมการว่า *"การระบุความละเอียดของสติกเกอร์ QR Code เป้าหมายไว้คงที่ที่ 200 พิกเซล มีผลทำให้ขนาดของบาดแผลผิดเพี้ยนหรือไม่?"*
ทางคณิตศาสตร์พิสูจน์ได้ว่า **ค่าพิกเซลปลายทางจะหักล้างและตัดทอนกันทิ้งไปในระบบสมการเสมอ** ดังนี้:
* **กรณีฟิกสติกเกอร์ QR Codeที่ 200 พิกเซล (ระบบจริงของเรา):**
  * พิกเซลแผลที่นับได้: 25,198 พิกเซล
  * ตัวคูณพื้นที่คงที่: 4.0 / (200 x 200) = 0.0001
  * พื้นที่แผลตารางเซนติเมตร: 25,198 x 0.0001 = **2.5198 ตารางเซนติเมตร**
* **กรณีทดลองเปลี่ยนมาฟิกสติกเกอร์ QR Codeที่ 400 พิกเซล (ความละเอียด 2 เท่า):**
  * พิกเซลแผลตรงจะถูกยืดขยายเพิ่มเป็น 4 เท่า: 100,792 พิกเซล
  * ตัวคูณพื้นที่คำนวณใหม่ได้: 4.0 / (400 x 400) = 0.000025
  * พื้นที่แผลตารางเซนติเมตร: 100,792 x 0.000025 = **2.5198 ตารางเซนติเมตร**

*ผลพิสูจน์ยืนยันว่า การระบุขนาดปลายทาง (เช่น 200 พิกเซล) ทำหน้าที่เพียงกำหนดความละเอียดของการประมวลผลเท่านั้น แต่ไม่มีผลทำให้ค่าขนาดพื้นที่จริงเปลี่ยนแปลงแม้แต่จุดทศนิยมเดียว*

## 📌 บทที่ 7: คำสำคัญและชื่ออัลกอริทึมสำหรับศึกษาต่อ (Keywords & Algorithms for Further Study)

หากต้องการนำไปเขียนในเล่มข้อเสนอโครงงาน บทความวิจัย หรือสไลด์นำเสนอเพื่อการสอบเพื่ออ้างอิงเชิงวิชาการสากล สามารถนำคำสำคัญเหล่านี้ไปสืบค้นต่อบนฐานข้อมูลวิชาการได้ทันทีครับ:

1. **การตรวจหาจุดอ้างอิงและตำแหน่งสติกเกอร์ QR Code (Fiducial Marker & QR Localization):**
   * **Keywords:** `Fiducial Marker`, `Visual Marker Calibration`, `QR Code Bounding Polygon`, `pyzbar library`, `OpenCV Contour Detection`

2. **การทำเซกเมนเทชันแผลด้วยปัญญาประสาทเทียม (Wound Segmentation & Deep Learning):**
   * **Keywords:** `Semantic Image Segmentation`, `U-Net Convolutional Network`, `EfficientNet-B4 Backbone Encoder`, `Pixel-level Classification`, `Sigmoid Activation Thresholding`

3. **การแปลงดึงระนาบตรงและพิกัดทรานส์ฟอร์ม (Homography & Perspective Transformation):**
   * **Keywords:** `Planar Homography`, `Perspective Projection Transformation Matrix (3x3 Matrix)`, `cv2.getPerspectiveTransform`, `cv2.warpPerspective`, `Projective Geometry`

4. **การชดเชยการลาดเอียงของกล้อง (Camera Tilt Compensation):**
   * **Keywords:** `Perspective Tilt Angle Correction`, `Perspective Cosine Law of Area Projection` (กฎโคไซน์การฉายพื้นที่ตามความลาดเอียง)

5. **อัลกอริทึมการคำนวณและวัดขนาดพิกเซล (Area Algorithms & Geometry):**
   * **Keywords:** `Bilinear Interpolation` (การขยายสเกลเฉลี่ยภาพ), `Euclidean Distance Formula` (การหาระยะห่างมุมกล่อง), `Shoelace Algorithm` or `Gauss's Area Formula` (สูตรหาพื้นที่รูปหลายเหลี่ยมคูณไขว้ทแยง)

6. **ดัชนีวัดความไม่มั่นคงและความเชื่อถือได้ของขอบแผล (Model Confidence & Entropy):**
   * **Keywords:** `Shannon Entropy in Image Processing` (ดัชนีวัดความเบลอขอบแผล), `Model Prediction Confidence Score`, `Segmentation Uncertainty Estimation`
