Overview & Architecture

คู่มือหลัก: ภาพรวมขั้นตอนการเตรียมฐานข้อมูล

คู่มือรวบรวมแผนการรันระบบและโรดแมปขั้นตอนการตั้งค่าโปรเจกต์ DFU

A
โครงสร้างสะพานเชื่อมโยงข้อมูล (Flow Diagram)

นี่คือขั้นตอนเวลาที่ระบบ Backend ทำงานร่วมกัน ตั้งแต่เริ่มประกอบคอมจำลอง Docker ไปจนถึง APIs สื่อสารจริง:

1. Docker Compose (ศูนย์บัญชาการ)
อ่านไฟล์ docker-compose.yml เพื่อเตรียมเปิดตู้ db (Postgres) และสร้างตู้ api (FastAPI)
2. Dockerfile & Requirements.txt (สร้างสิ่งแวดล้อม)
ลินุกซ์จำลองรันคำสั่ง pip install ติดตั้ง SQLAlchemy, OpenCV, และ pyzbar ไว้อย่างมิดชิดภายในตู้
3. SQLAlchemy Engine & Session (สายจ่ายพลังงาน)
เปิดสายคุยระหว่าง FastAPI และ PostgreSQL ผ่านพอร์ตจำลอง โดยมีการเช็คสายหลุดอัตโนมัติ
4. Alembic Migration (ผู้คุมเวอร์ชัน)
สแกนโครงร่างโมเดลคลาสใน models.py เพื่อนำไปแปลงเขียนตารางจริงลงดีบีโดยไม่ทำให้ข้อมูลเก่าสูญหาย
5. APIs & Dependency Injection (ด่านตรวจพร้อมยืม)
ผู้ใช้ร้องขอมา -> get_db ยืม Session ให้ API คิวรี -> เมื่อส่งคำตอบกลับเสร็จ ปิด Session อัตโนมัติ

B
สถาปัตยกรรมจัดกลุ่มโมดูลแบบแยกย่อย (Modular Directory Layout)

เพื่อรองรับโครงการขนาดปานกลาง-ใหญ่ และป้องกันปัญหา Import วนลูป (Circular Import) เราจัดสัดส่วนดังนี้:

  • `app/models.py`: รวมคลาสโครงร่างตาราง ORM ทั้งหมดไว้ที่นี่ เพื่อเขียนความสัมพันธ์ `relationship` เชื่อมหากันได้อย่างอิสระ
  • `app/modules/`: แยกกลุ่มโฟลเดอร์สำหรับเก็บฟังก์ชันประมวลผล (def) และตัวรับ APIs เช่น แยกงานคนไข้ที่ `patients/` และงานตัดขอบคำนวณแผลที่ `wounds/`
Step 1

การตั้งค่าไฟล์โครงข่ายภายนอก (Docker & Env)

การเตรียมฐานรันระบบจำลองเพื่อให้ทุกคนในทีมรันโค้ดได้ผลลัพธ์ตรงกัน

💡
ทำไมเครื่องคุณถึงไม่ต้องการลงไลบรารี? เพราะในขั้นตอนนี้เราจะบรรจุความต้องการทั้งหมดไปติดตั้งอยู่ในตู้ Docker ทั้งสิ้น ระบบหลัก Windows ของคุณจะไม่มีขยะติดตั้งเพิ่มขึ้นเลย

1
ปรับแต่งไฟล์ `.env`

สร้างไว้ที่โฟลเดอร์นอกสุดของโปรเจกต์ เพื่อเป็นที่รวมคีย์ลับรหัสผ่านของระบบ:

.env 
POSTGRES_USER=dfu_admin
POSTGRES_PASSWORD=dfu_password
POSTGRES_DB=dfu_database
POSTGRES_HOST=db
POSTGRES_PORT=5432

DATABASE_URL=postgresql://dfu_admin:dfu_password@localhost:5430/dfu_database
DATABASE_URL_DOCKER=postgresql://dfu_admin:dfu_password@db:5432/dfu_database
💡 ทำไมต้องแยก DATABASE_URL และ DATABASE_URL_DOCKER? (ต่างกันอย่างไร)

เนื่องจากโปรเจกต์ของเราจะรันอยู่บน "สองระบบเครือข่าย (Network Namespace) ที่แยกออกจากกัน" ดังนี้ครับ:

  • DATABASE_URL (โลกภายนอกตู้ - รันตรงบน Windows): ใช้เมื่อเราพิมพ์สั่งคำสั่งตรงบน PowerShell/CMD ใน Windows เช่น สั่งอัปเดตตารางฐานข้อมูล (alembic upgrade head) หรือสคริปต์ป้อนข้อมูลตัวตนคนไข้ (python seed.py) ตัวระบบ Windows จะเข้าถึง Postgres ผ่านพอร์ตสะพานภายนอกคือ localhost:5430
  • DATABASE_URL_DOCKER (โลกภายในตู้ปิด - รันจำลองบน Docker): ใช้เมื่อตัวแอป FastAPI (หลังบ้าน) ถูกสั่งให้บูตตัวเองรันอยู่อยู่ในตู้ปิดจำลอง โดยตู้แอปจะวิ่งไปต่อเชื่อมกับตู้ฐานข้อมูลผ่านสายแลนจำลองภายใน Docker (Bridge Network) โดยวิ่งเข้าหาชื่อเครื่องบริการฐานข้อมูลตรง ๆ คือ db และคุยผ่านพอร์ตรุ่นดั้งเดิมคือ 5432 (ไม่ชี้ไป localhost:5430 เพราะภายในตู้ API คำว่า localhost จะหมายถึงตัวแอปเอง และทำให้ต่อดีบีล้มเหลว)

2

3
สร้างแบบแปลนสร้างคอมพิวเตอร์จำลอง `Dockerfile`

เขียนสคริปต์นี้ไว้ที่ไฟล์ `server/Dockerfile`:

server/Dockerfile

WORKDIR /app

RUN apt-get update && apt-get install -y \

COPY . .

4
สร้างไฟล์ควบคุมการเปิดตู้จำลอง `docker-compose.yml`

เขียนสคริปต์นี้ไว้ที่ไฟล์ `docker-compose.yml` ที่โฟลเดอร์หลักนอกสุดของโครงการ:

Step 2

ระบบเชื่อมโยงและเปิดสัญญาณฐานข้อมูล (Session)

การจัดทำสายแจกจ่ายสัญญาณ (Connection Pool) ให้กับ API หลังบ้านของระบบ

1
ไฟล์โหลดคอนฟิก `config.py`

สร้างไฟล์นี้เพื่อให้ Pydantic ดึงตัวแปรจากไฟล์ `.env` ภายนอกมาใช้งานในระบบโดยอัตโนมัติ:

server/app/core/config.py 
from pydantic_settings import BaseSettings, SettingsConfigDict

class Settings(BaseSettings):
    PROJECT_NAME: str = "Deep Learning-Based System for Segmentation and Monitoring of Diabetic Foot Ulcer"
    API_V1_STR: str = "/api/v1"
    DATABASE_URL: str

    model_config = SettingsConfigDict(
        env_file="../.env", 
        env_file_encoding="utf-8", 
        extra="ignore"
    )

settings = Settings()

2
สร้างคลาสแม่สำหรับตารางฐานข้อมูล `base_class.py`

สร้างสคริปต์นี้เพื่อตั้งระบบแปลงคลาส ORM เป็นตารางอัตโนมัติ:

server/app/db/base_class.py 
from typing import Any
from sqlalchemy.orm import DeclarativeBase, declared_attr

class Base(DeclarativeBase):
    id: Any
    __name__: str

    @declared_attr
    def __tablename__(cls) -> str:
        return cls.__name__.lower()

3
สร้างสายสัญญาณและแจกจ่าย `session.py`

ควบคุมการต่อสายสัญญาณเข้าสู่ตู้ดีบีจำลอง:

server/app/db/session.py 
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker
from app.core.config import settings

engine = create_engine(settings.DATABASE_URL, pool_pre_ping=True)
SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)
Step 3

โมเดลโครงร่างฐานข้อมูล (SQLAlchemy Models)

การนิยามคลาสภาษา Python ทั้ง 7 ตารางหลักเพื่อป้อนลงฐานข้อมูล

1
ไฟล์สารบัญนำเข้าตารางรวม `app/models/__init__.py`

สร้างโฟลเดอร์ชื่อ server/app/models/ และเขียนสคริปต์สารบัญเพื่อรวบรวมไฟล์ตารางย่อย (คำเตือน: ไฟล์นี้ไม่ใช่ไฟล์สำหรับเขียนคอลัมน์ตาราง โค้ดชนิดข้อมูลและตัวแปรตารางจริง ๆ จะถูกอธิบายแยกย่อยไว้ในการ์ดข้อถัด ๆ ไปด้านล่าง เช่น role.py, user.py, patient.py...):

server/app/models/__init__.py 
from app.db.base_class import Base
from app.models.role import Role
from app.models.user import User
from app.models.nurse import Nurse
from app.models.patient import Patient
from app.models.body_part import BodyPart
from app.models.wound import Wound
from app.models.wound_record import WoundRecord
from app.models.appointment import Appointment

2
โมเดลบทบาทสิทธิ์ `app/models/role.py`

เขียนสคริปต์นี้ไว้ที่ server/app/models/role.py:

server/app/models/role.py 
from sqlalchemy import Column, String
from sqlalchemy.orm import relationship
from app.db.base_class import Base

class Role(Base):
    __tablename__ = "roles"
    role_id = Column(String(5), primary_key=True)
    role_name = Column(String(20), nullable=False)
    users = relationship("User", back_populates="role")
💡 คำอธิบายโครงสร้างตาราง roles:
  • role_id (String 5 ตัว): รหัสสิทธิ์สั้น ๆ เช่น ADMIN, NURSE, PATI เป็น Primary Key
  • role_name (String 20 ตัว): ชื่อภาษาไทยเพื่อใช้แสดงผลบน UI เช่น 'ผู้ดูแลระบบ', 'พยาบาล', 'ผู้ป่วย'
  • users: ผูกความสัมพันธ์ One-to-Many ไปยังตาราง User (1 บทบาทมีผู้ใช้สังกัดได้หลายคน)

3
โมเดลบัญชีสมาชิกหลัก `app/models/user.py`

เขียนสคริปต์นี้ไว้ที่ server/app/models/user.py:

server/app/models/user.py 
import datetime
from sqlalchemy import Column, String, DateTime, ForeignKey
from sqlalchemy.orm import relationship
from app.db.base_class import Base

class User(Base):
    __tablename__ = "users"
    user_id = Column(String(10), primary_key=True)
    username = Column(String(50), unique=True, nullable=False, index=True)
    password = Column(String(255), nullable=False)
    role_id = Column(String(5), ForeignKey("roles.role_id"), nullable=False)
    created_at = Column(DateTime, default=datetime.datetime.utcnow)
    role = relationship("Role", back_populates="users")
    nurse_profile = relationship("Nurse", uselist=False, back_populates="user")
    patient_profile = relationship("Patient", uselist=False, back_populates="user")
    records_added = relationship("WoundRecord", back_populates="nurse")
💡 คำอธิบายโครงสร้างตาราง users (ระบบล็อกอินหลัก):
  • user_id (String 10 ตัว): รหัสผู้ใช้งานที่ไม่ซ้ำกัน ทำหน้าที่เป็น Primary Key
  • username (String 50 ตัว): บัญชีล็อกอินหลัก ตั้งค่าแบบ unique=True ห้ามมีคนลงซ้ำ และใส่ index=True เพื่อให้สืบค้นตรวจชื่อได้ไวตอนล็อกอิน
  • password (String 255 ตัว): บรรจุรหัสผ่านที่แฮชเรียบร้อยแล้ว เพื่อความปลอดภัยทางข้อมูล
  • role_id (String 5 ตัว): คีย์นอก (ForeignKey) อ้างอิงสิทธิ์การเข้าถึงจากตาราง roles
  • nurse_profile / patient_profile (1-to-1 Relationship): การผูกโยงไปยังข้อมูลส่วนตัวพยาบาลหรือคนไข้ โดยใช้คำสั่ง uselist=False เพื่อจำกัดว่า 1 บัญชีผู้ล็อกอินจะสามารถผูกโยงข้อมูลตัวตนได้เพียง 1 ข้อมูลเท่านั้น

4
โมเดลประวัติพยาบาล `app/models/nurse.py`

เขียนสคริปต์นี้ไว้ที่ server/app/models/nurse.py:

server/app/models/nurse.py 
from sqlalchemy import Column, String, ForeignKey
from sqlalchemy.orm import relationship
from app.db.base_class import Base

class Nurse(Base):
    __tablename__ = "nurse"
    user_id = Column(String(10), ForeignKey("users.user_id"), primary_key=True)
    first_name = Column(String(50), nullable=False)
    last_name = Column(String(50), nullable=False)
    department = Column(String(100), nullable=True)
    user = relationship("User", back_populates="nurse_profile")
💡 คำอธิบายโครงสร้างตาราง nurse:
  • user_id (String 10 ตัว): เป็นทั้ง ForeignKey ชี้หาตาราง users และทำหน้าที่เป็น Primary Key ของตารางตัวเองไปพร้อมกัน เพื่อจำกัดสิทธิ์ความสัมพันธ์แบบ 1-to-1
  • first_name / last_name (String 50 ตัว): ชื่อจริงและนามสกุลจริงของพยาบาลผู้ตรวจแผล
  • department (String 100 ตัว): แผนกสังกัด เช่น แผนกผู้ป่วยนอก (OPD) หรือ คลินิกเบาหวาน

5
โมเดลประวัติคนไข้เบาหวาน `app/models/patient.py`

เขียนสคริปต์นี้ไว้ที่ server/app/models/patient.py:

server/app/models/patient.py 
import datetime
from sqlalchemy import Column, String, Date, ForeignKey
from sqlalchemy.orm import relationship
from app.db.base_class import Base

class Patient(Base):
    __tablename__ = "patients"
    HN = Column(String(50), primary_key=True, index=True)
    user_id = Column(String(10), ForeignKey("users.user_id"), nullable=True)
    first_name = Column(String(50), nullable=False)
    last_name = Column(String(50), nullable=False)
    birth_date = Column(Date, nullable=True)
    gender = Column(String(10), nullable=True)
    phone = Column(String(20), nullable=True)
    admit_date = Column(Date, default=datetime.date.today)
    user = relationship("User", back_populates="patient_profile")
    wounds = relationship("Wound", back_populates="patient")
    appointments = relationship("Appointment", back_populates="patient")
💡 คำอธิบายโครงสร้างตาราง patients:
  • HN (Hospital Number - String 50 ตัว): หมายเลขประจำตัวผู้ป่วยเวชระเบียนโรงพยาบาล เป็น Primary Key หลักใช้คุมภาพรวม
  • user_id: ไอดีเชื่อมตารางผู้ใช้ (ล็อกอิน) อนุญาตให้เป็น nullable=True ได้ ในกรณีที่คนไข้บางท่านยังไม่มีบัญชีสิทธิล็อกอิน (ใช้แค่ HN ในการตรวจแผลหน้าโรงพยาบาลอย่างเดียว)
  • admit_date (Date): วันเริ่มเข้ารับการรักษารอบติดตามผลแผลเบาหวาน
  • wounds: ผูกความสัมพันธ์ One-to-Many ไปยังตารางแผลทั้งหมดที่เกิดกับคนไข้ท่านนี้ (คนไข้ 1 คน สามารถเกิดแผลหลายจุดแยกจากกันได้)

6
โมเดลตำแหน่งร่างกายที่แผลเกิด `app/models/body_part.py`

เขียนสคริปต์นี้ไว้ที่ server/app/models/body_part.py:

server/app/models/body_part.py 
from sqlalchemy import Column, String
from sqlalchemy.orm import relationship
from app.db.base_class import Base

class BodyPart(Base):
    __tablename__ = "body_parts"
    body_part_id = Column(String(5), primary_key=True)
    body_part_name = Column(String(50), nullable=False)

💡 คำอธิบายโครงสร้างตาราง body_parts:
  • body_part_id (String 5 ตัว): รหัสตำแหน่งทางกายวิภาคสั้น เช่น FF (หน้าเท้า), HEEL (ส้นเท้า), PLAN (ฝ่าเท้า) เป็น Primary Key
  • body_part_name (String 50 ตัว): ชื่อตำแหน่งภาษาไทยแสดงผลบนกราฟฟิก

7
โมเดลจุดเกิดแผลหลักคนไข้ `app/models/wound.py`

เขียนสคริปต์นี้ไว้ที่ server/app/models/wound.py:

server/app/models/wound.py 
import datetime
from sqlalchemy import Column, String, DateTime, ForeignKey
from sqlalchemy.orm import relationship
from app.db.base_class import Base

class Wound(Base):
    __tablename__ = "wounds"
    wound_id = Column(String(10), primary_key=True)
    HN = Column(String(50), ForeignKey("patients.HN"), nullable=False)
    body_part_id = Column(String(5), ForeignKey("body_parts.body_part_id"), nullable=False)
    side = Column(String(10), nullable=False)
    created_at = Column(DateTime, default=datetime.datetime.utcnow)
    patient = relationship("Patient", back_populates="wounds")
    body_part = relationship("BodyPart", back_populates="wounds")
    records = relationship("WoundRecord", back_populates="wound")
💡 คำอธิบายโครงสร้างตาราง wounds (ตัวจัดกลุ่มแผลหลัก):
  • wound_id (String 10 ตัว): รหัสกลุ่มแผลหลัก เช่น W0001, W0002
  • HN (ForeignKey): ผูกกับเจ้าของแผลเพื่อสืบสาวว่าแผลเป็นของคนไข้คนไหน
  • body_part_id (ForeignKey): ตำแหน่งกายวิภาคอ้างอิงจากตาราง body_parts
  • side (String 10 ตัว): บันทึกข้างของเท้าที่เกิดแผล เช่น ซ้าย หรือ ขวา
  • records (Relationship): ผูกกับประวัติภาพถ่ายประเมินรายวัน (WoundRecord) แบบ One-to-Many ทำให้สามารถคำนวณอัตราความเร็วการเติบโตหรือลดขนาดของแผลตำแหน่งนี้ได้อย่างแม่นยำ

import datetime

💡 คำอธิบายตาราง wound_records (หัวใจหลักของผลงาน Deep Learning):
  • record_id (Integer, Primary Key): คีย์ออโต้รันเลข 1, 2, 3, 4 เพื่อจัดเรียงประวัติตามเวลา
  • wound_id (ForeignKey): ลิงก์ย้อนไปยังแผลแกนหลัก (ตาราง wounds) เพื่อระบุว่ารูปภาพนี้เป็นการสแกนของแผลในกลุ่มใด
  • user_id (ForeignKey): รหัสบัญชีพยาบาลผู้กดสั่งถ่ายรูปวิเคราะห์แผล
  • image_path (String 255 ตัว): ที่เก็บไฟล์รูปภาพต้นฉบับและผลลัพธ์การคาดการณ์ (Mask) บนฮาร์ดดิสก์
  • area_pixel (Integer): ขนาดพื้นที่ความกว้างของแผลในรูป นับตามจำนวนพิกเซล (ได้จากการสแกนขอบเขตแผลด้วยโมเดล Deep Learning)
  • area_cm2 (Float): ขนาดพื้นที่จริงที่แปลเป็นหน่วย ตารางเซนติเมตร ($cm^2$) โดยอัลกอริทึม OpenCV คำนวณเทียบพิกเซลขนาด 2x2 ซม. ของ QR Code ในรูปภาพ

Step 5

สคริปต์ป้อนข้อมูลตัวอย่างและการรันสแกนแผล (Seeding)

การป้อนสิทธิ์การเข้าถึง (Roles) และตำแหน่งร่างกาย (BodyParts) ก่อนเริ่มทดลองงานจริง

1
สร้างไฟล์สคริปต์สุ่มป้อนข้อมูลเริ่มต้น `seed.py`

สร้างไฟล์นี้ไว้ใน `server/app/db/seed.py` เพื่อจัดแจงป้อนข้อมูลเริ่มต้น:

server/app/db/seed.py 
import sys
import os
sys.path.insert(0, os.path.abspath(os.path.join(os.path.dirname(__file__), '../..')))

from app.db.session import SessionLocal
from app.models import Role, BodyPart

def seed_initial_data():
    db = SessionLocal()
    try:
        roles_data = [
            Role(role_id="ADMIN", role_name="ผู้ดูแลระบบ"),
            Role(role_id="NURSE", role_name="พยาบาล"),
            Role(role_id="PATI", role_name="ผู้ป่วย")
        ]
        
        parts_data = [
            BodyPart(body_part_id="FF", body_part_name="Forefoot (หน้าเท้า)"),
            BodyPart(body_part_id="MF", body_part_name="Midfoot (กลางฝ่าเท้า)"),
            BodyPart(body_part_id="HEEL", body_part_name="Heel (ส้นเท้า)"),
            BodyPart(body_part_id="ANKL", body_part_name="Ankle (ข้อเท้า)"),
            BodyPart(body_part_id="DORS", body_part_name="Dorsum (หลังเท้า)"),
            BodyPart(body_part_id="PLAN", body_part_name="Plantar (ฝ่าเท้า)")
        ]
        
        for role in roles_data:
            if not db.query(Role).filter_by(role_id=role.role_id).first():
                db.add(role)
                
        for part in parts_data:
            if not db.query(BodyPart).filter_by(body_part_id=part.body_part_id).first():
                db.add(part)
                
        db.commit()
        print("✅ ป้อนข้อมูล Roles และ Body Parts เริ่มต้นลงฐานข้อมูลสำเร็จ!")
    except Exception as e:
        print(f"❌ เกิดข้อผิดพลาดในการใส่ข้อมูลตั้งต้น: {e}")
        db.rollback()
    finally:
        db.close()

if __name__ == "__main__":
    seed_initial_data()

app = FastAPI(title=settings.PROJECT_NAME)

    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()

@app.get("/")
def read_root():
    return {"message": "FastAPI และระบบฐานข้อมูลพร้อมใช้งานแล้ว!"}

@app.get("/test-db-connection", response_model=List[dict])
def test_db_connection(db: Session = Depends(get_db)):
    parts = db.query(BodyPart).all()
    return [{"id": p.body_part_id, "name": p.body_part_name} for p in parts]
